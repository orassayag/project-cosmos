## Stage 5 — useAgentChat hook (committed 2026-10-03T10:02:14Z)
**Files:** client/src/hooks/useAgentChat.ts (new), client/src/hooks/__tests__/useAgentChat.test.ts (new), client/src/components/askStream.ts
**What was built:** `useAgentChat({ onAction? })` returns `{ messages, isStreaming, send, stop, newChat, retry }` and owns the in-flight request (AbortController, streaming flag, partial reply), so closing the chat window never aborts or loses a reply (I6). `send` trims/ignores blank, stops any running reply first, builds the request with `toRequestMessages`. `stop()` keeps the partial as `status: 'stopped'`, re-sent as `${partial}\n\n(reply stopped by the visitor)` (or just the note when empty) so turns alternate (I3). `newChat()` = stop + clear; per-request ids drop late chunks. Errors (I7) become `error` messages with `toAskErrorMessage` text; `retry(errorMessageId)` removes the failed question + error and re-asks; errors/failed replies never sent back. Finished replies store `usage` (`{ inputTokens, outputTokens }`). `askStream.ts`: new `streamAskMessages(messages, signal, onEvent)` posts `{ messages }`; `streamAskAnswer` wraps it, so AskPanel/App unchanged.
**Key decisions:** Provider error text lives in `ASK_ERROR_MESSAGES`/`toAskErrorMessage` in `askStream.ts` (no providerErrors.ts). `AgentChatMessage` = `AgentUserMessage { id, role:'user', content }` | `AgentReplyMessage { id, role:'assistant', content, status:'streaming'|'done'|'stopped'|'failed', usage: TokenUsage|null }` | `AgentErrorMessage { id, role:'error', errorCode, content, question }`; ids `chat-N`. Exported `toChatHistory(messages)` (skips errors and failed/streaming replies, adds note to stopped) and `STOPPED_REPLY_NOTE`. Error after partial tokens → partial kept as `failed`, never sent back; empty placeholder removed. `send` while streaming stops first (stage 6 may still disable send while streaming). Messages mirrored in a ref so stop()+send() in the same tick read latest history. Hook aborts only on its own unmount (App). No `onAnswerStart`; stage 6 detects answer start via `status === 'streaming' && content !== ''`. Token count text left to UI (use existing `formatUsage`).
